# Governed API guide

The version-one API exposes the decision workflow under `/v1`. It prepares and
governs commercial recommendations; it cannot send messages or perform an
external commercial action.

## Contract rules

- Every mutation requires an `Idempotency-Key` header. Repeating the same key
  and content returns the original result with `replayed: true`; changing the
  content produces `409 idempotency_conflict`.
- Mutation paths and bodies identify exact object revisions. A mismatched object
  identity or revision produces `409 path_revision_mismatch`.
- Every mutation requires an authenticated human actor. In test and conformity
  profiles, send `X-Test-Actor-Id`, `X-Test-Actor-Name`,
  `X-Test-Actor-Kind: HUMAN`, and `X-Test-Auth-Signature`. The signature is
  lowercase hex HMAC-SHA256 over `<actor UUID>:<display name>` using
  `TEST_AUTH_SIGNING_KEY`.
- The test adapter is unavailable in local and local-live profiles. A deployment
  must supply its production authentication and application-service adapters.
- Authorization requests contain only the exact CAO revision, terminal decision,
  and rationale. Authorized action and scope are copied server-side from that
  current CAO; clients cannot author or broaden them.
- Clients may send `X-Request-ID`; the server echoes a safe value on every
  response. Error bodies include the same request ID and a stable error code.
- `GET .../execution-eligibility` evaluates eligibility only. Its response
  always reports `external_action_performed: false`; no execute/send endpoint
  exists.

## Workflow routes

1. `POST /v1/decision-cycles`
2. `POST /v1/decision-cycles/{id}/capacity-revisions`
3. `POST /v1/decision-cycles/{id}/discovery-runs`
4. `POST /v1/candidates/{id}/revisions/{revision}/evidence-runs`
5. `POST /v1/candidates/{id}/revisions/{revision}/eligibility-evaluations`
6. `POST /v1/candidates/{id}/revisions/{revision}/assessment-runs`
7. `POST /v1/decision-cycles/{id}/qualified-snapshots`
8. `POST /v1/qualified-snapshots/{id}/revisions/{revision}/comparison-runs`
9. `POST /v1/qualified-snapshots/{id}/revisions/{revision}/allocation-runs`
10. `POST /v1/allocations/{id}/revisions/{revision}/action-preparation-runs`
11. `POST /v1/commercial-actions/{id}/revisions/{revision}/release-evaluations`
12. `POST /v1/commercial-actions/{id}/revisions/{revision}/review-submissions`
13. `POST /v1/commercial-actions/{id}/revisions/{revision}/authorization-decisions`
14. `GET /v1/commercial-actions/{id}/revisions/{revision}/execution-eligibility`
15. `POST /v1/objects/{id}/revisions/{revision}/reassessment-evaluations`
16. `GET /v1/decision-cycles/{id}/operator-view`

`GET /v1/decision-cycles/{id}` is the current cycle read endpoint. Request and
response schemas are authoritative in [openapi.json](openapi.json), generated by:

```bash
.venv/bin/python scripts/export_openapi.py
```

The corresponding read-only server-rendered interface is available at
`GET /operator` and `GET /operator/cycles/{id}`. These presentation routes are
excluded from OpenAPI because they return HTML rather than API resources.

## Stable errors

The API maps validation, missing-revision, revision-conflict, idempotency,
in-progress, phase-precondition/hold, specialist-contract, and agent-run failures
to redacted error envelopes. Internal exception text is not returned to clients.
